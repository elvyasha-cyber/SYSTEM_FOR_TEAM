# Система знаний команды

Программа хранит документы команды, по вопросу находит абзацы и отвечает дословными цитатами. Если опереться не на что, ответ — «Данных недостаточно.», а в истории остаётся причина проверки.

Сейчас это одна программа на Python. Она не ходит в интернет, не требует отдельных пакетов и держит всё в файле SQLite. Ниже у каждого пункта сказано, что останется и что изменится, если позже поиск заменит векторный индекс, а черновик ответа — внешняя модель.

## Новая машина

На новом компьютере нужна папка проекта и один из двух способов запуска.

Через Python: установлен Python 3.10 или новее. Отдельное окружение, список пакетов и ключи не нужны. При первом запуске программа сама создаёт пустую базу `data\kb.sqlite`. Список документов в панели будет пустым, пока документ не добавят.

Через Docker: установлен и запущен Docker. Python на самом компьютере тогда не нужен, он уже внутри образа. Первый раз Docker скачивает образ Python из интернета. Папка базы в команде ниже начинается пустой и не связана с чужим файлом `kb.sqlite`.

Дальше. На новой машине дополнительно понадобятся адрес внешней модели, ключ и доступ к векторному индексу. Пока программа их не читает, для запуска достаточно Python или Docker.

## Запуск

Отдельное окружение и установка пакетов не требуются.

Из папки проекта:

```powershell
python -m server
```

Панель открывается по адресу http://127.0.0.1:8080. База появляется сама: `data\kb.sqlite`.

Дальше. Когда появятся клиент модели и клиент векторного индекса, перед запуском добавится установка пакетов. Команда `python -m server` и адрес панели останутся теми же.

## Переменные окружения

Их можно не задавать: работают значения по умолчанию.

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `KB_HOST` | `127.0.0.1` | адрес, на котором программа слушает |
| `KB_PORT` | `8080` | порт |
| `KB_DB` | `data\kb.sqlite` | файл базы |

Пример для другого порта:

```powershell
$env:KB_PORT = "8090"
python -m server
```

Секретов у программы нет. Ключей внешней модели и Pinecone она не читает: такие строки ничего бы не подключили, пока код их не использует.

Дальше. Адрес модели и пустой ключ индекса добавятся в тот же список вместе с кодом, который их читает. Настоящий ключ в репозиторий не кладётся.

## Docker

Образ — один сервис. Файл `docker-compose.yml` не нужен.

```powershell
docker build -t kb-team .
docker run --rm -p 8080:8080 -v kb-data:/app/data kb-team
```

Внутри контейнера программа слушает `0.0.0.0`, снаружи панели это порт `8080`. Папка `kb-data` сохраняет базу между запусками. Если порт `8080` уже занят программой, запущенной через Python, на хосте берут другой порт, например `-p 8090:8080`, и открывают http://127.0.0.1:8090.

Дальше. Внешняя модель и Pinecone останутся чужими сервисами: программа будет ходить к ним по адресу и ключу, а не поднимать их рядом. Свой контейнер для векторного хранилища появится только если индекс решат держать у себя. Тогда рядом с программой опишут второй контейнер.

## Панель, поиск и база

Браузер открывает панель. Панель спрашивает программу на порту `8080`. Программа читает и пишет `data\kb.sqlite`.

В базе четыре таблицы. `documents` хранит название и полный текст. `snippets` хранит абзацы: текст режется по пустой строке, и поиск идёт по ним. `qa_runs` хранит вопрос, ответ, цитаты и причину проверки. `audit_runs` хранит каждый запрос: что пришло, что ушло и сколько это заняло.

Новый документ добавляют на вкладке «Документы». Новый ответ виден на вкладке «История». Файлы в `tests_data` программа сама не открывает и в базу не переносит.

Дальше. SQLite останется местом для документов, истории и аудита. Поиск по словам в `server\search.py` сменится запросом к индексу, но наружу по-прежнему вернётся идентификатор документа и текст фрагмента. Абзац, который уйдёт в индекс, останется в `snippets`: иначе цитату нечем подтвердить.

## Примеры запросов

Сервер должен уже слушать http://127.0.0.1:8080. В PowerShell команду вызывают как `curl.exe`. Знак `--%` нужен, чтобы кавычки внутри JSON дошли до curl.

Добавить документ:

```powershell
curl.exe --% -s -X POST "http://127.0.0.1:8080/kb/documents" -H "Content-Type: application/json; charset=utf-8" --data-binary "{\"title\":\"Правила работы команды\",\"text\":\"Оператор отвечает клиенту не позже следующего рабочего дня.\"}"
```

Спросить базу:

```powershell
curl.exe --% -s -X POST "http://127.0.0.1:8080/kb/ask" -H "Content-Type: application/json; charset=utf-8" --data-binary "{\"question\":\"К какому сроку оператор должен ответить клиенту?\"}"
```

Собрать ответ по уже переданному контексту:

```powershell
curl.exe --% -s -X POST "http://127.0.0.1:8080/ai/answer_with_sources" -H "Content-Type: application/json; charset=utf-8" --data-binary "{\"question\":\"К какому сроку оператор должен ответить клиенту?\",\"context\":\"Оператор отвечает клиенту не позже следующего рабочего дня. Молчание дольше этого срока считается пропущенным ответом.\"}"
```

Перед вопросом к базе в ней должен быть документ с нужным фактом. Иначе ответ будет «Данных недостаточно.». Таблица десяти вопросов и ожидаемых проверок лежит в `tests_data\README.md`.

Дальше. Форма этих трёх запросов сохранится. `POST /kb/ask` начнёт брать фрагменты из индекса. Черновик в `POST /ai/answer_with_sources` вместо копирования предложений вызовет внешнюю модель. Контроль останется прежним: цитата должна быть дословной, а при низкой уверенности или словах не из контекста ответ заменяется на «Данных недостаточно.».

## Кто видит базу

Сейчас база одна на всех, кто открыл адрес панели. Отдельного входа нет. Документы, вопросы и история общие.

Дальше. Знания команды останутся общими. Разделять будут человека, который спросил: в истории и аудите появится, кто отправил вопрос.

## Тестовые файлы

Это конечные наборы на диске. Запуск сервера их не читает.

| Файл | Что внутри |
|---|---|
| `tests_data\kb_documents.jsonl` | 5 документов |
| `tests_data\kb_questions.jsonl` | 10 вопросов: 7 с ответом в этих документах, 3 без |
| `tests_data\inputs.jsonl` | те же 10 вопросов |
| `tests_data\README.md` | примеры `curl` и таблица ожидаемой проверки |

Живые документы и ответы пишутся только в `data\kb.sqlite`.

Дальше. Эти файлы останутся фиксированным набором для проверки. Новые документы, добавленные в панели, пополняют базу, а не тестовые файлы.
